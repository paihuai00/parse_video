# 抖音实现与验收证据（2026-10-20）

本记录只保存脱敏结果。样本分享 token、作品 ID、Cookie、API Key 和签名媒体 URL 均未写入仓库。样本代号沿用研究阶段的 V1、V2、I1、I2。

## 自动获取结果

四个输入分别在新的匿名 Playwright/Chromium 进程和浏览器上下文中运行，使用 20 秒完整期限。获取层自动展开短链、核对最终作品 ID，并从目标作品的 React Flight 状态或详情响应读取完整对象；没有使用日常浏览器配置或手工复制的媒体地址。

| 样本 | 结果 | 第一次耗时 | 第二次独立上下文 | 说明 |
| --- | --- | ---: | ---: | --- |
| V1 | 成功，普通视频，1 个主 MP4、独立封面 | 3.20 秒 | 3.07 秒 | 最终镜像复验 3.58 秒；主视频有 MP4 正向证据 |
| V2 | 成功，普通视频，1 个主 MP4、独立封面 | 3.51 秒 | 3.16 秒 | 最终镜像复验 3.64 秒；主视频有 MP4 正向证据 |
| I1 | 成功，静态图文，完整结果为 1 张正文图 | 1.92 秒 | 1.79 秒 | 最终镜像复验 2.25 秒；图片为 1260×2388；零时长伴奏不输出 |
| I2 | `UNSUPPORTED_CONTENT` | 1.69 秒 | 1.66 秒 | 最终镜像复验 1.75 秒；唯一图片槽位带 2.033 秒动态 MP4 |

I1 的完整作品对象实际只有一个图片槽位，因此返回一张是完整图集，不是从多图中只取一张。I2 没有降级成静态图片成功，避免调用方误以为取得完整内容。

审查阶段修复了两个真实链路问题：详情响应现在只接受最终目标 ID，不会被先到达的其他作品响应占位；React Flight 脚本在浏览器侧按 2 MiB 累计上限逐项读取，并继续收集加载过程中追加的脚本，直到数量稳定。修复后用同一 512 MiB、256 PID、只读根、64 MiB `/tmp`、seccomp 和非 root 镜像重新执行四样本：V1 5.48 秒、V2 6.01 秒、I1 4.59 秒成功，I2 在 4.87 秒返回 `UNSUPPORTED_CONTENT`。V1/V2 代表 MP4 与 I1 代表 WebP 均再次独立读取 1024 字节，HTTP 206、MIME 和文件头相符。复验输出只含样本代号和脱敏摘要，没有持久化短链 token、作品 ID 或签名媒体 URL。

## 媒体可读性

代表视频和图片使用独立、无 Cookie、无 Referer 的 HTTP 会话读取 1024 字节：

- V1 主视频：HTTP 206、`video/mp4`，1024 字节，文件头含 MP4 `ftyp`；主机为精确允许的 `v11-weba.douyinvod.com`。
- V2 主视频：HTTP 206、`video/mp4`，1024 字节，文件头含 MP4 `ftyp`；主机为精确允许的 `v11-weba.douyinvod.com`。
- I1 正文图：HTTP 206、`image/webp`，1024 字节，文件头为 WebP；主机为精确允许的 `p3-pc-sign.douyinpic.com`（另一次独立运行得到同样受信的 `p9-pc-sign.douyinpic.com` 候选）。

复验曾发现同一码率槽位的第一个允许地址可能落到当前返回 403 的备用 CDN，而同槽 `v11-weba` 地址返回 206。实现已改为对经样本验证的精确主机使用明确优先级，并加入离线回归。修复后的最终镜像中，V1、V2、I1 各连续两次文件头读取均为 206 且签名相符。修复过程另观察到 V2 一次临时 403，新的匿名刷新随即恢复 206；因此运行时仍如实标记 `verification=not_checked`，不承诺每条上游签名地址永久可用。

该检查证明返回直链在测试出口可被独立读取，不表示已完整下载、解码播放，也不保证签名地址长期有效。运行时响应继续标记 `verification=not_checked`。

## 出站与资源边界

- 浏览器所有 HTTPS 请求先进入仅监听回环地址的 CONNECT 代理。代理按精确主机白名单检查请求，对 DNS 的全部结果执行公网地址校验，并把隧道连接固定到已检查的 IP；DNS 与连接共享 5 秒上限。
- 页面、脚本和详情请求分别受资源类型及主机规则限制；图片、媒体、字体、样式和后台服务请求在解析阶段被拦截。
- 默认每次最多 500 个浏览器请求、32 MiB 双向隧道流量和 2 MiB 状态数据；浏览器并发默认为 1，并继续服从服务共享的 admission、限流、缓存、请求合并和 20 秒完整期限。
- 每次抖音解析创建独立浏览器进程和匿名上下文。正常、异常、取消与超时路径关闭上下文、浏览器、Playwright 驱动和回环代理；代理退出会取消并等待已接收的连接处理任务。抖音浏览器只存在于抖音适配器，小红书 HTTP 适配器不依赖其启动。

## 容器与回归

镜像固定 `playwright==1.64.0` 及配套 Chromium，应用保持 UID/GID 10001、单 Uvicorn worker、只读根文件系统、64 MiB `/tmp` tmpfs、512 MiB 内存和 256 PID 上限。完整 Chromium 使用 root 所有的 sandbox helper，并应用 Playwright 官方 Docker seccomp profile 所需的用户命名空间例外；运行应用本身仍为非 root。

本地 `linux/arm64` 容器对最终实现的四样本真实请求保持上述结果。多轮解析后的 cgroup 记录为 PID 峰值 166/256，`oom=0`、`oom_kill=0`；内存触及 512 MiB 上限并发生回收，请求仍完成。浏览器进程清理后只剩 init 与 Uvicorn，内存回落至约 64 MiB、`pids.current=5`。该结果证明单并发在本机限制下可运行，也表明没有充足内存余量；目标 VPS 应保留并发 1 并复测，不能据此提高并发。目标 VPS 原生架构、HTTPS 接入和回滚演练仍需部署者执行。

另以 1 秒完整期限启动最终镜像的独立受限容器，V1 在 1.12 秒返回 504 `UPSTREAM_TIMEOUT`；等待清理后进程表只剩 init 与 Uvicorn、`pids.current=5`、`oom=0`。随后旧小红书入口仍能按原文案校验输入，说明浏览器超时没有破坏旧路由进程状态。

离线回归覆盖抖音 URL、状态读取、动态追加脚本的有界读取、目标详情响应绑定、媒体完整性、同槽备用地址选择、CONNECT 出站代理的 DNS/连接时限与 handler 回收、统一 API、跨入口小红书缓存复用、旧契约和浏览器故障隔离。Python 3.12 全套测试通过；Ruff、mypy、compileall、OpenAPI JSON、Compose 配置和镜像构建也均通过。
