# 分享链接访问差异证据

日期：2026-11-04。用户授权对同一笔记的手机短链和 PC 分享长链进行分析。完整输入、分享 token、笔记 ID、Cookie、页面与媒体 URL 不保存在任务中。

后续进展：research/alternative-acquisition.md 已记录 safari184_ios 匿名获取匹配移动端笔记与有效静态图片的正向证据。本文保留桌面/路径对照的历史失败；下文浏览器实验建议现已降为后备，当前优先方案见 design.md 的移动端适配。

## 已验证结果

公网 request ID：手机短链 `3ebd04ce-8137-4441-8ef2-e5cd55a7b466`；PC 长链 `b43a130e-5742-44c5-9181-30ad88b4cf15`。只验证了公网返回结果，没有线上逐跳追踪。

本机使用项目 `XiaohongshuClient`、curl_cffi 0.13.0、chrome136、匿名会话、trust_env=False、TLS 校验、逐跳公网 DNS 和 CurlOpt.RESOLVE 地址绑定、20 秒原始总期限。Python 为独立诊断环境 3.15.2，非项目声明的 3.12，不代表生产运行时验收。

## 参数与路径对照

- 两者指向同一笔记 ID。
- xsec_token 值不同；手机来源为 app_share，PC 来源为 pc_share。
- 短链跳转携带完整 app 分享参数；客户端未删掉这些查询值。
- 仅做受控路径对照：app 原始查询换为 explore 路径、PC 原始查询换为 discovery/item 路径、PC 原始 explore，均返回 302 到 /404，携带 errorCode=-510001。
- 路径对照采用独立匿名 curl_cffi 会话，并非完整浏览器实验；它只说明这些路径/参数组合在本次环境仍失败。
- 没有证据支持改写 xsec_source、拼接/生成 token 或删减查询值能恢复访问。现有两种原始分享方式本身都失败，不能将问题直接归因于分享来源不同。

## 错误页诊断

为识别状态页，在独立诊断请求中严格限定 https、精确 www.xiaohongshu.com、443、/404、无用户凭证；重新验证全部 DNS 地址为公网并绑定，保持原始 20 秒总期限、TLS 和 2 MiB 响应上限，不自动跟随。

该 /404 页面返回 HTTP 200，98316 字节，标题为“小红书 - 你访问的页面不见了”。页面存在 initial-state 标记，但未命中本次检查的显式删除、笔记不存在、登录、验证码、访问频繁等文案；没有提取到目标笔记成功内容。

此诊断不改变产品可抓取路径。HTTP 302 /404、200 错误页标题及 -510001 的组合仍不足以证明原笔记删除，也没有经过可靠资料核实 -510001 的语义，不能硬编码为 NOTE_NOT_FOUND 或某种风控错误。

## 根因层次

1. 已确认的程序缺陷：app/parser/client.py:157 跟进重定向后，app/parser/client.py:105 先进行 URL/DNS 校验；app/parser/url_rules.py:79 只认笔记路径，导致上游状态页被报成用户 INVALID_URL；app/parser/client.py:180 的 classify_page 执行不到。
2. 已确认的访问差异：用户报告手机可打开；当前匿名 HTTP 客户端对两个分享入口均拿不到笔记。手机 App/浏览器可使用账号、会话、设备能力、JS 和不同网络，尚未逐项隔离。
3. 用户后续已确认：电脑浏览器已登录小红书，并能看到完整笔记内容。该事实支持“内容在用户会话下可访问”，不支持“匿名客户端也应可获取”。登录会话是重要待隔离因素，但还不能证明本笔记必须登录。
4. 用户进一步提供退出登录后的截图：手机号/扫码登录弹窗遮挡页面，但背景仍可见笔记画面、作者和正文。可确认该浏览器状态出现登录提示；截图不能确定目标笔记完整媒体数据是否已到达客户端，也不能排除退出前已加载状态或缓存。未复制截图或其中二维码到仓库。
5. 未确认：全新未登录上下文中，弹窗出现时是否存在可完整提取的目标笔记数据；同一服务器出口的全新匿名浏览器是否能取得目标笔记；-510001 的稳定公开含义；出口 IP、token 时效/上下文或会话初始化各自的影响。

因此，修正错误码是必要修复，但不能单独作为本样本“解析成功”的解决方案。匿名浏览器兜底必须先有同出口、无账号、相同笔记匹配的成功证据，再决定是否建设；若只有已登录环境成功，则需要另行评估登录会话产品范围。

## 截图带来的额外分类风险

代码检查确认 app/parser/client.py:57 会在全页 HTML 命中“登录后查看”“请先登录”或 login-container 时直接报 UPSTREAM_LOGIN_REQUIRED；app/parser/client.py:180 在返回 PageResponse 前调用该分类，app/parser/adapters.py:39 才解码并选择目标笔记数据。

这意味着“完整目标笔记数据与登录弹窗模板同时存在”可能被过早拦截；目前没有该场景的真实 HTML/网络数据，不能宣称此截图已复现这个缺陷。前面真实 curl 链路仍然在 /404 跳转路径校验处终止，尚未到达该分类函数，两者须分别验证。

下一实验应使用全新匿名上下文，检查目标 ID 对应的完整状态/媒体信息是否实际存在，避免沿用用户已登录 profile 的退出前内存、缓存或先前页面。不是通过隐藏弹窗证明可访问。若确实只有登录提示而无完整内容，返回登录要求；若完整内容已匿名下发，则研究以目标数据完整性区分登录提示与真正登录阻断，同时保留明确挑战和访问拒绝语义。

## 当前可执行建议

- 保留完整原始分享参数，用户无需为了本问题改 curl JSON 或 refresh 字段。
- 先修状态跳转分类和脱敏诊断；未知状态页归为通用上游错误，明确登录/挑战/缺失才分别映射。
- 下一实验在实际部署出口使用全新匿名浏览器，与当前 HTTP 客户端对照，确认是否取得目标 note ID 的完整内容；不把“页面打开”或推荐内容当成成功。
- 为先隔离账号变量，可在用户同一电脑/网络用全新未登录浏览器访问同一完整链接，比较是否能看到完整笔记。若此处失败而已登录成功，支持会话相关限制；若此处成功而服务器匿名失败，则继续检查服务器出口或客户端初始化差异。无痕窗口若实际仍登录，不算匿名对照。
- 匿名浏览器成功后，才设计受控浏览器获取：复用有界 CONNECT 代理思路，但单独建立小红书真实所需精确资源主机证据，保持总期限、资源预算、独立上下文和清理。不能直接复制抖音允许主机或在普通 HTTP 路径执行任意 JS。
- 若同出口匿名浏览器失败，则该实验不能支持浏览器兜底；按登录/访问限制证据返回明确失败，继续隔离账号会话与出口差异，不承诺修复后成功。
