## 环境与方式

- 本机系统 DNS 已恢复，`v.douyin.com`、`www.iesdouyin.com`、`www.douyin.com` 均解析出公网地址；网页检索工具仍无法打开四个短链。
- 临时目录内创建隔离环境，使用 `curl_cffi==0.13.0`、`chrome136`，不修改项目代码或依赖。
- 首轮每个样本使用独立匿名会话、手机 User-Agent、同站 Referer；TLS 校验、手动重定向、逐跳精确主机检查、公网 DNS 检查与连接 IP 绑定均启用。
- 探测设置连接 5 秒、最多 3 次跳转、解压响应 2 MiB 上限。临时诊断设置 25 秒 HTTP 链路预算，DNS 使用系统阻塞解析，故此次脚本不构成生产 20 秒全链路期限验收。
- 仅在内存中处理页面；没有保存原始 HTML、Cookie、作品 ID、完整短链或媒体签名地址；没有执行页面脚本。

## 后续受限诊断

- 第二次检查四条原始短链时，详情页均返回 HTTP 200、2,492 字节 HTML，不再含可读取的 `_ROUTER_DATA` 或 `RENDER_DATA`。
- 对 V1、I1 各选一个代表样本，改用与 Chrome 指纹匹配的默认桌面 User-Agent，仍得到相同大小的页面；其中出现 `document.cookie`、`location.reload`，没有 title 或可用作品状态。
- 对 V1、I1 使用手机 User-Agent，并尝试去除分享页查询参数的规范地址，结果相同。这只是独立诊断，不能据此建议生产代码删除访问相关查询参数。
- 这些现象提示存在会话/脚本前置处理或访问策略影响，但不足以确定具体机制，更不能证明账号登录、签名逆向或常驻浏览器是必要条件。停止重复 HTTP 请求，避免用反复重试替代证据。

## 当前可确定的解析路径

1. 受控展开短链，取得真实作品路径与 ID。
2. 获取对应 `share/video` 或 `share/note` 页面。
3. 从内嵌状态读取目标作品，严格匹配 ID；本轮已证实状态容器存在，但尚未打通目标对象提取。
4. 取得作品对象后，视频验证主 MP4 与封面；图文提取完整有序图片。字段候选继续以 [上游调研](../../.trellis/tasks/10-19-douyin-media-parser/research/upstream-options.md) 为定位线索，不当作已确认契约。
5. 对代表媒体做有界可读性验证，之后才可声明成功。

## 下一项研究

需要在一次可取得完整状态的正常访问中检查 `loaderData` 的键、错误结构和实际作品 ID 字段。可用隔离浏览器做诊断对照，区分纯 HTTP 响应与正常页面加载；浏览器观察到内容也不等于生产匿名 HTTP 方案可用。只有取得证据后，才决定现有无浏览器方案能否继续，以及是否需要重新评审运行方式。

本轮没有启用浏览器、账号 Cookie、签名生成或外部解析服务；没有启动实现。P0「视频和图文各至少一个真实成功」门槛仍未通过。
