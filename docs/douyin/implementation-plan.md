# 分阶段实施与验收计划

2026-10-20 已完成本地实现、真实样本验证、共享服务与统一接口接入。目标 VPS 原生架构、HTTPS 和真实调用方验收仍待部署者执行；任务保持 in progress。

## P0：最小真实解析实现与基础部署验证（第一项实施）

历史起点：[P0 实测](p0-data-loading-2026-10-19.md)确认四个分享页的 `itemId` 匹配目标，但初始状态没有媒体。后续实现已取得完整作品对象并通过本地样本与资源验收，结果见[实现验收证据](implementation-evidence-2026-10-20.md)。

- [x] 已确认允许服务端浏览器候选，优先实现真实解析；不再以纯 HTTP 无代码验证成功作为开工条件。
- [x] 明确浏览器出站、上下文隔离和资源上限，并在 Docker Desktop `linux/arm64` 验证无头浏览器/基础容器启动。
- [x] 实现可独立运行的最小获取与归一化链路，用真实输入完成下面 A–C 验证后再公开抖音 API。

### P0-A：定位作品对象

- [x] 选择 V1/I1 为浏览器诊断代表；四样本均完成分享页引导状态检查。
- [x] 逐级检查 `loaderData` 路由键与 `errors`，记录脱敏结构和扫描完整性；四样本均未因扫描截断而漏掉已读取的状态。
- [x] 核对最终路径与 `itemId`，四样本均为匹配的 19 位字符串；该绑定仅证明引导状态目标，不代表取得完整作品。
- [x] 读取 React Flight 包装状态和详情 JSON，限制状态总字节；不执行表达式，不对任意字符串无限递归解码。
- [x] 解释早期“未匹配”：漏查 `itemId`，且取得的初始状态确实缺媒体；异步详情接口的尝试尚未取得作品。只有 `captcha` 字符串不构成验证码证据。
- [x] 取得视频、图文各一个真实完整作品对象；测试 fixture 仅保留最小脱敏字段，不含可用签名 URL。

产出：一个视频与一个图文的真实、最小脱敏作品对象，以及“详情路径 → 状态容器 → 作品 ID → 媒体列表”的字段映射表。不会把完整 HTML 或可用签名 URL 作为 fixture 提交。

### P0-B：服务端浏览器获取与生命周期

- [x] 使用新的匿名上下文，按无头/容器运行模式获取代表样本；捕获目标详情响应或可验证的完整页面数据，仅保存脱敏结构证据。
- [x] 每次使用新的浏览器进程和匿名上下文，不导入用户 Cookie、持久化站点存储或 Service Worker 状态。
- [x] 确认完整数据来自桌面页 React Flight 状态或后续详情响应，并自动匹配目标作品。
- [x] 第一方移动分享页脚本存在异步详情加载；匿名 HTTP 详情尝试未成功。桌面浏览器此次成功所用的实际详情响应仍未捕获，不能直接等同于移动页接口。
- [x] 登录、验证、不可见状态使用页面证据分类，不借用用户已登录会话。
- [x] 完成浏览器所有连接的出站控制、资源限制、异常与取消回收；测试浏览器不可用时小红书仍可解析。
- [x] 四样本正常加载不依赖账号会话、验证码处理或其他范围外机制；若目标部署实测改变这一结论，再记录证据并提出范围变更。

浏览器候选的依赖与必要资源成本已确认。具体依赖版本、代码拆分、上下文管理及资源测量由实施处理；实际解析成功仍须用独立匿名上下文和目标部署模式证明，不能用桌面浏览器单次显示代替。

### P0-C：验证图文与视频的实际输出

- [x] 视频：确认目标作品的主视频候选与封面，只有格式字段、`.mp4` 路径或 `mime_type=video_mp4` 才作为 MP4 正向证据。
- [x] 图文：取得全部正文图片，区分同槽候选与不同图片槽，保留原顺序并检查动态部分。
- [x] 记录格式证据、字段单位和精确 CDN 主机；每个媒体只保留一条合格候选，不改签名、不替换域名、不推断无水印。
- [x] 使用独立新 HTTP 会话、不带 Cookie/Referer，对 V1 视频及 I1 正文图片各读取 1024 字节：206 MP4 / 206 WebP，文件头相符；V1 结合目标播放器非零画面尺寸确认视频证据。该检查不等于完整作品结构、图集或全程播放验收。
- [x] V1 与 I1 媒体在独立、无 Cookie/Referer 会话可读；目标 VPS 和真实调用方网络仍需分别验收。
- [x] 在不同的新匿名会话中低频重复成功案例，记录时点和出口；不据此推导总体成功率。
- [x] 用与生产一致的总 20 秒期限和其余既有限制复核；审查修复后的受限镜像中，三个支持样本在 4.59–6.01 秒内完成解析。

P0 退出门槛：至少一个普通视频、一个静态图文取得完整目标媒体并通过代表资源可读性验证；其余两个样本逐一验收，仍公开可访问且属于首版范围的样本也必须成功。若有失效/不支持的样本，记录依据，不静默跳过。阶段输出是最小可运行解析、字段映射、脱敏 fixtures、基础容器及资源检查记录。普通实现缺陷继续修复；只有明确范围冲突才返回规划，不把失败判定本身作为完成。

P0 结论见[实现验收证据](implementation-evidence-2026-10-20.md)：V1/V2 普通视频、I1 完整单图静态图文成功；I2 含动态 MP4，按首版范围返回 `UNSUPPORTED_CONTENT`。

## P4：验证与交付

现有 `scripts/probe.py` 的路由、媒体白名单和 Referer 都依赖小红书。后续验证工具需按平台选择策略，不能直接把抖音 URL 传入旧工具就作为正确验收；常规测试仍保持离线。

| 范围 | 必须覆盖 |
| --- | --- |
| URL/网络 | 四样本所示短链形状、已证实详情路径、伪造/未知域、私网 DNS、跨平台跳转、超预算/超体积 |
| 状态/媒体 | 目标 ID 非首项、图序及图数、中间坏图、跨槽重复图、同槽备用 URL、图文占位 video、变体选择一致性、仅音频/HLS、未知 CDN、动态图文拒绝 |
| 共享机制 | 两入口同密钥配额、跨入口小红书缓存复用、平台缓存隔离、refresh、等待容量、跨入口合并失败的独立文案/请求 ID、一个调用取消而另一个仍继续、超时清理 |
| 契约 | 新旧路由请求/响应、额外字段拒绝、十进制 ID 字符串、旧 24 位 ID 约束、所有小红书示例/Live Photo |
| 错误/日志 | 框架错误 envelope、平台准确措辞、旧文案回归、无原始 URL/token/Cookie/正文泄漏 |
| 部署 | 代理新旧路径、容器启动/健康、目标 VPS DNS/TLS/出口及调用方下载 |
| 浏览器 | 全请求出站限制、新匿名上下文、全链路期限、数量/体积预算、超时与崩溃回收、浏览器失败不阻断小红书 |

已执行的离线命令：

```sh
ruff format --check app tests scripts
ruff check app tests scripts
mypy app
pytest -q
python -m compileall app tests scripts
python -m json.tool docs/openapi.json >/dev/null
docker compose config --quiet
```

真实样本验证独立于离线测试。四个输入分别报告成功媒体数或有证据支持的失败类别；仍公开可访问且属于首版范围的四个样本均需解析成功。验收至少包含一个视频、一个图文的匿名成功及调用方可读证据；失效作品可使用用户补充的同类样本，并记录替换原因。网页获取、媒体提取、有界可读、完整下载/播放分别记录，文件头检查不能声称已完成整段播放。

## 风险文件、上线与回滚

影响文件主要是 `app/services/parse_service.py`、`app/parser/client.py`、`app/models.py`、`app/api/routes.py`、`app/errors.py`、`app/api/error_handlers.py`、`app/main.py`、契约测试和 Nginx 示例。已有小红书解析器尽量薄封装，避免无关重命名。

每阶段保留独立验证结果；P1 必须可单独回退。发布前保留既有小红书可运行镜像和配置；若统一入口或共享机制出现问题，恢复之前镜像与匹配的代理配置，确认旧入口和健康检查。缓存只在内存，不涉及数据迁移；部署回滚可能中断新入口调用，不能承诺无影响。

本地实现结论：无需登录、代理媒体、付费服务、扩大 20 秒对外时限或提高 512 MiB 容器内存即可通过现有样本与本地容器验收。目标 VPS 原生架构、HTTPS、出口和调用方媒体访问仍属于部署验收，不能由本地结果替代。
