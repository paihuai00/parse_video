# 排查小红书短链解析 NETWORK_ERROR

## Goal

只读追踪用户上报错误、验证授权短链、记录证据和修复建议；本轮不修改产品代码。

## Requirements

- R1：梳理后端入口、调度、短链跳转、页面状态提取和媒体归一化调用链。
- R2：定位用户上报的 `NETWORK_ERROR` 与本仓库错误契约之间的关系，区分事实与推断。
- R3：对用户提供的链接执行有界匿名请求，比较系统 curl 与固定 `curl_cffi==0.13.0` / `chrome136` 的行为。
- R4：记录代码证据、复测结果、测试缺口和建议的最小修复范围。
- R5：不记录 API Key、完整分享查询参数、HTML 或签名媒体 URL。
- R6：根据用户后续要求启动本地服务并切换为 Docker，验证最新样本；测试服务器公网接口并记录公网接入层诊断。

## Acceptance Criteria

- [x] 说明 `NETWORK_ERROR` 是否为当前后端定义的错误码。
- [x] 记录真实请求的脱敏跳转链，以及复测环境和时间的限制。
- [x] 对发现的问题给出文件位置与可验证的复现依据。
- [x] 明确还需要哪些线上证据才能归因历史事件。
- [x] 产品代码保持不变，分析记录保存在本任务目录。
- [x] 本地 Docker 健康且最新样本解析成功；公网故障层已定位，用户确认服务器已修复并要求归档。

## Background

- 用户日志：小程序 `pages/index/index` 的 `onParse`；版本 `1.6.3`；接收时间 `2026-10-30T04:50:26.560Z`；fingerprint `fb339cb05e3e89a0b37e0caaf3e8400a723a1521`。
- 本仓库为 FastAPI 后端，不包含小程序请求和错误映射代码。用户已明确同意创建任务并记录结论。
- 用户随后要求启动本地服务供其测试；已启动 `127.0.0.1:8000`，健康检查 200，真实链接请求复现 502 `MEDIA_NOT_FOUND`。

## Out of Scope

- 修改产品代码、操作远端服务或配置、引入平台账号或 Cookie、绕过访问验证。用户另行授权的本地启动、Docker 构建与公网请求验证已完成。
- 在缺少线上日志时把当前本机结果等同于历史线上根因。

## Deliverable

- `research/diagnosis.md`：排查结论、最终根因与验证依据。用户确认服务器已修复，本次分析任务完成归档；独立的 CDN 白名单兼容及登录跳转分类发现保留记录，后续实施需另行确定范围。
