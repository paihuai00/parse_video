# 复用小红书接口新增抖音视频与图文解析

状态：in progress；2026-10-20 已完成本地实现、真实样本与媒体可读性验证，目标 VPS 验收待执行。

## 目标与价值

核心目标是实际解析出抖音普通视频和完整静态图文，让调用方取得对应作品的媒体地址。复用小红书请求及媒体响应方式、保留旧调用兼容性，是实现该目标的接口约束；仅完成接口或模拟响应不构成交付。

## 背景与已确认事实

- 用户初始要求创建任务、新建抖音 Markdown 专属目录，并先规划、不实现；本轮要求检查规划是否仍有待确认事项。
- 用户后续已确认新增 `POST /api/v1/parse` 自动识别平台，保留旧小红书接口。
- 2026-10-20 用户认可上一轮交付方案：允许受控服务端浏览器作为抖音获取方式候选，接受必要依赖及资源成本，以真实解析成功优先；先做最小可运行解析，再接入共用接口及部署验收。
- 现有请求、媒体结构和基础设施可以复用，但 `app/api/routes.py:25` 只有小红书入口，`app/models.py:104`、`:113` 限定小红书 ID，`app/services/parse_service.py:105` 写死小红书状态解析。
- 历史 P0 记录确认四个分享页的初始引导状态只有匹配的 `itemId`，不含媒体。当前受控浏览器实现已在新的匿名上下文中自动取得 V1/V2 普通视频和 I1 的完整单图静态图文，代表媒体通过独立有界读取；I2 的唯一图片槽位带动态 MP4，按首版范围返回 `UNSUPPORTED_CONTENT`。本地容器与资源验收已完成，目标 VPS 原生架构、HTTPS、出口和实际调用方仍待部署验收；详见[实现验收证据](../../../docs/douyin/implementation-evidence-2026-10-20.md)。

## 需求

- **R1 接口兼容**：统一入口支持两平台，旧入口继续仅小红书；复用 `url`、`refresh`、鉴权、envelope、媒体字段、错误码，不破坏小红书已有图文/视频/Live Photo 语义及原 ID 约束。
- **R2 视频解析**：受支持抖音普通视频返回一个有明确 MP4 证据的主视频和可选独立封面；元数据缺失保留 null。
- **R3 图文解析**：受支持抖音静态图文按原顺序返回完整正文图片，不混入封面或背景音乐，不静默遗漏无法解析的媒体。
- **R4 访问与资源边界**：允许受控服务端浏览器，使用独立匿名上下文与有界资源，不增加账号登录或媒体代理。两个入口共同消耗现有服务资源配额；浏览器故障不得使旧小红书功能不可用。
- **R5 错误与证据**：能区分无效 URL、删除、登录/验证、平台限流、未知结构、缺媒体与超时；不将失败包装成空成功。真实成功需有独立可核查记录。
- **R6 文档与交付记录**：`docs/douyin/` 存放复用分析、样本研究、技术设计和实施验收 Markdown；Trellis 记录需求、设计、执行顺序与研究上下文，区分历史探测、已确认决策与实际功能验收。

## 验收条件

- **AC1 → R1**：新入口对受支持的两平台 URL 使用相同请求形状；旧路由、24 位 ID 约束、小红书全部现有示例及 Live Photo 行为通过回归。
- **AC2 → R2**：视频结果 `type=video`、`images=[]`、一个 MP4、独立可选封面；目标作品匹配，无音频/HLS 伪装视频。
- **AC3 → R3**：图文 `type=image`、有序非空 `images`、从 1 开始的 index、`videos=[]`、`cover=null`，不丢图不乱序。
- **AC4 → R4**：跨入口限流/容量共享，平台缓存不串用，refresh/取消/超时语义保持；恶意 URL 和不安全跳转在连接前被拒绝。浏览器导航、子资源与后续请求有受控出站边界，容器运行、匿名上下文隔离、超时/崩溃回收及小红书故障隔离有验证记录。
- **AC5 → R5**：四样本各自有脱敏结果；至少一个视频和一个图文完成匿名解析与独立调用方的代表媒体可读验证；其他仍公开可访问且属于首版范围的样本也须成功。仅失败分类通过不等于功能完成；原样本失效须记录同类替代依据。
- **AC6 → R6**：接口、部署与验收文档随实现同步；任务在目标 VPS 验收前保持 in progress，不以规划、mock 或错误分类代替功能结果。

## 范围外

分享整段文案直接作为 API 输入、批量/作者主页/评论采集、图文背景音乐导出、抖音动态照片与未知混合媒体、直播、图文合成视频、水印处理、转码、媒体代理/存储、永久链接、登录 Cookie/验证码处理/签名逆向或付费解析服务。受控浏览器已纳入候选范围，其可部署性由第一阶段实测决定。
