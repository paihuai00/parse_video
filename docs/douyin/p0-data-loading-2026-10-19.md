## 1. 修正“状态内没有目标 ID”的判断

四条短链仍为一次 302 跳转后取得 200 分享页，视频路径为 `www.iesdouyin.com/share/video/<id>/`，图文为 `/share/note/<id>/`。HTML 约 35–37 KB。

`window._ROUTER_DATA.loaderData` 的实际结构摘要：

| 项目 | 视频 V1/V2 | 图文 I1/I2 |
| --- | --- | --- |
| 路由键 | `video_layout`、`video_(id)/page` | `note_layout`、`note_(id)/page` |
| 实际 ID 字段 | `itemId`，19 位十进制字符串，与最终路径相符 | 同左 |
| 根 `errors` | null | null |
| 页面配置 | `renderInSSR=1`、`isSpider=false` | 同左 |
| 有界结构扫描 | 13 个节点，未触及截断上限 | 11 个节点，未触及截断上限 |
| 作品/媒体对象 | 无 `videoInfoRes`、`item_list`、`aweme_detail`、`images`、`video` 或 `play_addr` | 同左 |

上一轮只匹配 `aweme_id` / `awemeId`，因此漏掉了引导状态中的 `itemId`。补上这个字段只能确认当前页面目标，不能得到媒体：已读取的状态主要是页面配置、路由、设备/分享上下文及实验开关，不是完整作品对象。`errors=null` 也不代表媒体存在。

观察到客户端 loader 可以异步取得作品，再形成 `videoInfoRes`。共享脚本有两个请求函数：

- `/web/api/v2/aweme/iteminfo/`：`item_ids`，以及可选的作品类型、分享上下文、`reflow_id` 等参数。图文 loader 也引用此函数，不能仅按名称断定它只用于视频。
- `/web/api/v2/aweme/slidesinfo/`：`aweme_ids`、`aweme_type`、`aid`、`request_source` 等参数。存在此函数不等于当前图文页实际使用它。

请求包装还会使用匿名设备/分享上下文，启用 `withCredentials`；浏览器侧 `reflow_id` 的处理不能假设为原字段简单透传。本轮没有实现签名或加密参数生成，也没有提取浏览器 Cookie。

这些证据支持“初始 HTML 可能只有引导状态，作品需要后续加载”。下面浏览器验证使用桌面作品页；未捕获其详情响应，**不能把移动分享页的上述接口认定为桌面页这次成功的数据来源**。

## 3. 受限匿名 HTTP 接口尝试

| 尝试 | 结果 | 可得结论 |
| --- | --- | --- |
| V1：`iteminfo`，基本 `item_ids` 参数 | HTTP 200，空响应体 | HTTP 成功不代表有作品 |
| 四样本：`slidesinfo`，ID 数组及 `request_source` | HTTP 200；JSON `status_code=0`，`aweme_details=null`，`filter_list[].reason=8`，ID 与各自目标相符 | 四次均未取得详情；reason 8 含义未验证 |
| I1：同一个新匿名会话依次取短链、分享页，再带已观察的常规参数请求 `slidesinfo` | 仍为上述空详情和 reason 8 | 仅补常规上下文未解决 |
| V1：同一新匿名会话请求 `iteminfo`，常规上下文及空 `reflow_id` | HTTP 200；JSON `status_code=11110`，`status_msg=encrypt_data_miss` | 该次请求缺少服务端要求的数据；不能推断为账号登录要求 |

reason 8 不映射为“已删除”“需要登录”或“无权限”。`status_code=0` 搭配空详情不能生成成功响应。直接 HTTP 获取桌面页也未取得可解析媒体状态；本轮不继续枚举参数或反复更换指纹。

## 4. 浏览器与媒体读取证据

浏览器正常打开 V1、I1 桌面作品页；页面显示登录入口，本轮没有登录、处理验证码或导出账号/匿名 Cookie。工具未证明该浏览器站点存储为全新隔离状态，因此只记录“本轮未登录操作、页面显示未登录入口”，不宣称已排除既有匿名状态的影响。

V1 的目标播放器有非零画面尺寸、24.6 秒时长和已加载的数据；对应媒体不是仅音轨容器。没有完成整段播放。I1 正文图片在 DOM 中与背景重复图、推荐项、头像同时出现，不能把全页 `img` 列表直接当图集。I1 另有一个 `video` 元素使用 MP3 地址，画面尺寸为 0；这是背景音频线索，不应将图文误分类为普通视频。

独立读取使用新 `curl_cffi==0.13.0` 会话、`chrome136`，不发送 Cookie 或 Referer；请求 `Range: bytes=0-1023`，设置实际读取上限、TLS 校验、公网 DNS 检查和连接 IP 绑定。没有下载完整媒体。

| 检查 | V1 视频 | I1 正文图片 |
| --- | --- | --- |
| 实际 CDN 主机 | `v11-weba.douyinvod.com` | `p3-pc-sign.douyinpic.com` |
| HTTP / MIME | 206 / `video/mp4` | 206 / `image/webp` |
| Content-Range | `bytes 0-1023/2475024` | `bytes 0-1023/36844` |
| 实际读取 | 1,024 字节 | 1,024 字节 |
| 文件头 | ISO BMFF `ftyp` | WebP |

成功只说明所观察的签名地址在本次、本机出口可独立读取。不证明长期有效、无水印、其他出口可读、完整图集或整段下载/播放；不能把这两个主机扩展成通配 CDN 白名单。浏览器读取曾多次超时，也尚无稳定耗时数据。

## 5. 下一阶段如何收敛

1. **先补完整作品数据。** 以 I1 为优先，确认图集总数、原始顺序、每槽候选地址和动态内容标记；V1 补齐主视频与封面的结构关联。DOM 中看见单张图片不足以生成完整解析结果。
2. **明确数据获取方案。** 对照正常页面数据来源，判断能否在新的匿名 HTTP 会话中独立复现。继续沿用已批准的无浏览器边界；如仅能依赖浏览器，则先提出部署、并发、超时与会话成本的方案供选择，不自动改生产架构。
3. **覆盖 V2/I2 并复验。** 当前不能报告四条都成功；补齐后再进行独立客户端、全链路资源预算及目标 VPS 验证。
4. **通过 P0 后才推进接口改造。** 仍采用统一 `/api/v1/parse`、保留旧小红书入口，共享请求/媒体模型、缓存和限流；抖音获取与归一化留在平台适配器内。

本轮未形成真实完整成功 payload，故未伪造成功 fixture。原始页面、完整作品 ID、短链 token、Cookie、设备标识和带签名媒体 URL 不写入仓库；此处只保留脱敏结构与验证结果。
