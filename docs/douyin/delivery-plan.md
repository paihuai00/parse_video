# 以实际解析成功为目标的实施方案

创建日期：2026-10-19。实施日期：2026-10-20。用户认可的浏览器范围与交付顺序已完成本地实现和验证；目标 VPS 验收待执行。

## 核心交付

用户进一步明确：核心目标是能够解析抖音内容。完成标准是调用 API 后得到对应作品的视频或完整有序图文及可读媒体地址；仅有统一接口、错误分类、模拟数据或浏览器中看见内容都不算完成。

保留已确认的接口选择：新增 `POST /api/v1/parse`，复用小红书的请求、媒体响应、鉴权和服务调度；旧小红书入口与行为保持兼容。

## 已确认的获取方式

原规划将“生产只用匿名 HTTP、无浏览器”列为技术边界。当前证据只支持浏览器能取得代表媒体，尚不支持纯 HTTP 能独立完成地址发现；也未证明无头浏览器在目标部署环境能成功。继续将纯 HTTP 成功作为所有实现工作的前置条件，会使核心能力迟迟无法得到可执行验证。

已确认：允许引入受控服务端浏览器作为抖音获取方式的候选，把最小真实解析实现作为第一阶段；浏览器方案通过基础部署验证后方可接入正式请求链路。纯 HTTP 若后来被证实可独立复现，可作为优化替换，无需改变公共接口。该选择不等于断言浏览器是唯一可行方法。

用户已接受必要的浏览器依赖及部署、内存、延迟成本，不重复确认该选择。具体浏览器版本、代码拆分和生命周期策略由工程实现确定；实际资源用量、20 秒总预算及自动解析成功率由测试提供证据。

## 第一阶段：先交付真实解析的最小实现

进入实施后，先在开发环境按目标部署方式运行无头浏览器，尽早验证基础容器启动和资源预算，再完成以下实现与验证；不先搭一套无法取得数据的公共接口：

1. 对输入短链/作品链接进行目标校验，取得确定的作品 ID。
2. 使用独立匿名浏览器上下文正常加载目标页面，从目标详情响应或可验证的页面数据中取得完整作品。不得使用用户日常浏览器配置或手工复制媒体 URL 充当自动解析。
3. 视频输出目标主 MP4 与可选封面；图文输出完整正文图片列表及顺序，排除推荐图片、背景重复图和伴奏音频；未知动态/混合内容保持明确不支持。
4. 独立客户端对代表视频和图片验证可读性，四条仍可访问且属于范围的用户样本均须成功；分至少两次独立上下文运行记录可重复性，不据此宣称普遍成功率。
5. 以可执行结果固定最小脱敏字段样本，再验证取消、超时、资源回收及部署条件。

此阶段允许为验证写最小代码；成功标准仍为真实作品解析，不能用 mock 代替。失败时保留具体差距与证据，不能进入接口发布阶段或把异常包装成成功。浏览器不自动加入账号登录、验证码处理或签名逆向机制。

## 第二阶段：接入共用接口

第一阶段通过后，将抖音获取与媒体归一化封装为平台适配器，接入统一入口。共用业务流程、缓存、鉴权、限流和错误 envelope；保留旧小红书传输、ID 约束、图文/视频/Live Photo 语义。

浏览器获取是平台内部实现，不向调用方暴露浏览器控制、Cookie 或额外登录步骤。服务仍只返回临时媒体地址，不增加媒体代理、保存或转码。

浏览器启动失败、崩溃或抖音获取异常不得连带使旧小红书解析不可用；生命周期管理和异常隔离列入回归验收。

## 第三阶段：部署与交付验收

- 浏览器进程及上下文有界，退出、取消和超时必须关闭资源；两平台共享服务总配额，可额外限制浏览器并发但不能绕过全局容量。
- 小红书既有 20 秒等契约保持；抖音也先按既有总预算验证。若实测无法满足，记录耗时并提出明确调整，不暗中放宽所有请求的期限。
- 浏览器请求包含脚本、子资源和后续接口，必须在实现前设计并验证出站边界；仅校验首次页面 URL 或复用 curl 的 DNS 校验不等于浏览器所有连接受控。
- 容器必须包含匹配的浏览器与系统依赖，维持非 root、浏览器沙箱及资源清理；不通过禁用安全机制换取启动成功。
- 验收包含四样本结果、代表媒体可读性、小红书回归、目标部署环境自动执行和有据可查的失败分类。没有部署证据就不声明已可生产使用。

Playwright/Chromium 是候选工具，具体依赖版本在实施时固定。官方说明浏览器上下文可隔离站点状态，而 Docker 运行需要额外浏览器/系统依赖及相应进程配置；这些是采用浏览器的实际成本：[上下文隔离](https://playwright.dev/python/docs/browser-contexts)、[Docker 部署](https://playwright.dev/python/docs/docker)。上述官方能力不证明抖音站点一定可解析。

实施结果：镜像固定 Playwright 与配套 Chromium，完整浏览器使用 Linux sandbox helper，应用保持非 root；Compose 增加 PID 上限与 init。浏览器 HTTPS 经回环 CONNECT 代理执行精确主机、公网 DNS 和已检查 IP 绑定，独立限制请求数、隧道字节和并发。共享 `ParseService` 通过适配器复用资源控制，浏览器只在抖音链路按请求创建和回收。

## 现有规划的适用范围

P0–P3 已按依赖顺序完成；任务保持 in progress，直到目标 VPS 和真实调用方完成 P4 部署验收。历史研究文档继续保留其当时结论，当前实现状态以技术设计、实施计划和实现验收证据为准。

该任务仍是一个端到端交付：最小解析 → 共用接口 → 部署验收有顺序依赖；不会把只有接口的部分单独标为完成。

## 实施结论

本地实测没有出现必须登录、购买服务、代理媒体、提高 20 秒承诺或升级 512 MiB 容器内存的证据。V1/V2 普通视频和 I1 完整静态图文成功；I2 含动态 MP4，按已确认范围返回 `UNSUPPORTED_CONTENT`。目标 VPS 原生架构、HTTPS、出口和调用方下载仍需部署验收。
