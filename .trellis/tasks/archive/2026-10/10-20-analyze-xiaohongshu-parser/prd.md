# 分析当前小红书解析逻辑

## Goal

基于当前代码、Git 历史、契约文档和离线测试，确认 `/api/v1/parse` 与 `/api/v1/xiaohongshu/parse` 接入前后的 HTTP 请求逻辑是否存在重复或遗留，区分新接口仍依赖的生产路径与可选辅助请求代码，并在用户确认范围后删除真正不再需要的部分。

## Background

- 分析基线为提交 `fd8e72cf966679330be13ae0022d83443c4ea8d1`（2026-10-20）。
- 小红书同时通过旧入口 `POST /api/v1/xiaohongshu/parse` 和统一入口 `POST /api/v1/parse` 对外提供；两者复用同一个 `XiaohongshuAdapter` 和同一份内部结果。
- 现有对外目标是返回全部有序正文图片、与图片绑定的 Live Photo MP4，或普通视频的一个 MP4 及独立封面。
- Git 历史显示 `9132a09` 首先实现 `/api/v1/xiaohongshu/parse` 和小红书页面抓取，`04037bd` 新增 `/api/v1/parse` 并通过适配器复用原实现；没有留下第二套小红书生产请求客户端。

## Requirements

- **R1 HTTP 接口与调度**：列出全部对外 HTTP 路由、方法、鉴权、请求体、主要响应和代理暴露情况，并说明平台选择、限流、缓存、请求合并、排队与总时限的先后顺序。
- **R2 页面获取**：说明支持的 URL 形态、DNS/SSRF 防护、逐跳重定向、连接固定、响应上限、重试和页面分类。
- **R3 状态与媒体解析**：说明 `window.__INITIAL_STATE__` 的提取边界、按目标 note ID 选择、图片/Live Photo/普通视频的归一化和候选排序。
- **R4 输出与失败语义**：说明公开响应模型、旧入口兼容、错误码、日志和明确的不验证范围。
- **R5 风险与证据**：以文件行号、可重现输入和离线测试结果支撑结论，区分已确认缺口和有意的 fail-closed 设计。
- **R6 遗留请求审计**：从 Git 历史和当前引用关系区分生产必需、兼容必需、运维辅助和可删除代码；删除范围必须获得用户明确确认。

## Acceptance Criteria

- [x] **AC1 → R1**：研究记录列出全部 3 个对外 HTTP 路由及请求契约，区分公开入口与上游 HTTP 请求，并能从两个解析入口追踪到 `XiaohongshuAdapter` 和共享资源控制。
- [x] **AC2 → R2**：研究记录列出允许的主机/路径、查询参数保留、逐跳校验、公网 DNS 限制、HTML 上限和总时限。
- [x] **AC3 → R3**：研究记录说明精确 note 选择、媒体主机白名单、MP4 正向证据、Live Photo 归属和视频排序策略。
- [x] **AC4 → R4**：研究记录包含输出不变量、错误分类、缓存语义和媒体未实时校验的限制。
- [x] **AC5 → R5**：完成小红书相关离线回归，并记录一个经可重现验证的完整性缺口。
- [x] **AC6 → R6**：确认当前不存在未引用的第二套小红书生产请求实现，并列出唯一脱离服务运行链路的 HTTP 探测脚本及其删除影响。
